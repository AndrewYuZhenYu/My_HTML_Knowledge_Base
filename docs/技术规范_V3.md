# 知栈（HTML Knowledge Base）V3：整体规范与技术说明

> **产品定位**：这是一套以阅读体验为核心的个人知识库，而不是展示型后台页面。现有成熟 Markdown 知识笔记是长期维护的**权威源文件**，HTML 是高质量、可交互的阅读与知识组织载体。
>
> **V3 修订范围**：①恢复 Obsidian Callout 多色语义；②让思维导图可靠打开，并在 JavaScript 失效时仍可阅读；③提供真实可运行的多 Markdown 批量导入流程。此前字号、行距、公式 SVG、函数图等阅读特性予以保留。

## 1. 不可妥协的设计原则

1. **完整迁移优先**：不得为了页面更美观而缩写、改写、重新组织原始 Markdown 中的知识内容、公式、标题和例题。新增的图表、导图入口应当与原文内容区分。
2. **阅读优先**：默认正文 19 px、行距 1.85、阅读宽度 850 px；用户可调字体为 16–26 px、行距为 1.5–2.15，并可开启宽屏或专注阅读。保留长篇教材适合的标题大小和段落间距。
3. **语义色彩**：不同 Callout 类型必须有明显但不过度浓艳的语义色区别；一套颜色同时适配浅色与深色模式；颜色不仅靠背景，也通过左边框与标题体现。
4. **数学排版**：保留原 LaTeX 源式，构建阶段将数学公式渲染为嵌入式 SVG。公式随页面缩放，允许较长的陈列公式横向滚动，不能因窄屏截断。
5. **交互可选**：任何不可或缺的知识文字和链接都不能只存在于 JavaScript 异步生成结果中。交互失败时必须有可读的原生 HTML 回退。
6. **跨文件组织**：每篇笔记生成自己的 HTML；课程目录、页面路径和全局搜索由构建器根据文件扫描自动生成。
7. **可追溯和可回滚**：`sources/` 保存完整原始 Markdown；生成的 HTML 可以重新构建，代码与内容用 Git 管理。
8. **离线运行优先**：输出 HTML 不依赖外网 CDN。内容展示、公式、导图、基本索引均能直接在本地浏览器读取。

## 2. 技术栈与职责

| 层次 | 选用技术 | 实际职责 |
|---|---|---|
| 源内容 | Markdown / Obsidian Callout | 维护课程知识与数学公式 |
| HTML 解析及构建 | Python 3.11+ / Mistune 3 / BeautifulSoup 4 | 批量扫描、Markdown 转 HTML、Callout 分类、标题 ID、页面导航、静态搜索数据 |
| 数学公式 | Node.js / MathJax 3 | **构建时**将 `$...$` 与 `$$...$$` 转换为内联 SVG；不要求读者在线加载 MathJax |
| 阅读交互 | 原生 JavaScript | 字号、行距、主题、专注模式、搜索、页内目录 |
| 样式 | 原生 CSS | 专业阅读排版、响应式布局、语义色彩 |
| 思维导图 | 原生 HTML `<details>` + SVG + 少量 JavaScript | 双侧布局、原生折叠、知识锚点、辅助缩放与连接线 |
| 函数图像 | 原生 SVG / JavaScript | 页面内实时计算绘图，如麦克斯韦速率分布 |
| 数据与导航 | JSON / 生成的 `search-data.js` | 课程定义、可选命名覆盖、全文索引 |
| 管理 | Git、浏览器 | 备份与日常阅读；当前不需要数据库 |

**当前实际搜索实现**是构建时生成的本地 `search-data.js`，并非 Pagefind。随着规模增长可升级 Pagefind 或其他检索工具，但不能以未来方案冒充 V3 已有功能。

## 3. Callout 颜色规范

| Callout 类型（含同义） | 用途 | 色彩 |
|---|---|---|
| `note` | 一般注释 | 深蓝 `#2563eb` |
| `abstract`、`tldr` | 摘要、章节引导 | 青蓝 `#0891b2` |
| `info`、`todo` | 信息、待办 | 浅蓝 `#0284c7` |
| `important` | 重点知识 | 紫色 `#8b5cf6` |
| `tip`、`hint` | 技巧、提示 | 青绿 `#0d9488` |
| `success`、`check`、`done` | 成功与检查 | 绿色 `#16a34a` |
| `example` | 例题 | 绿色 `#16a34a` |
| `question`、`help`、`faq` | 问题 | 黄色 `#ca8a04` |
| `warning`、`caution`、`attention` | 警告 | 橙色 `#ea580c` |
| `failure`、`fail`、`missing`、`danger`、`error` | 错误、危险 | 红色 `#dc2626` |
| `bug` | 缺陷 | 玫红 `#db2777` |
| `summary` | 章节总结 | 靛蓝 `#4f46e5` |
| `quote`、`cite` | 引用 | 灰蓝 `#64748b` |

**视觉规则**：背景使用低透明度颜色混合；左边框明确标识语义；标题文字强调语义色；正文继续采用阅读主色。深色模式增加背景混合浓度而非简单反转颜色。所有色彩规则集中在 `assets/style.css`，未来可整站统一更换。

输入保持原来 Obsidian 语法，不需要修改：

```md
> [!important] 核心公式
> $$U=\frac{i}{2}\nu RT$$

> [!example] 例题
> 先求自由度，再计算内能。

> [!warning] 易错点
> 物质的量为 $\nu$，分子数密度为 $n$。
```

目前支持常用标准 Callout 和普通嵌套引用结构。某些插件私有语法、复杂自定义 Callout 折叠语义以及自定义 CSS 仍需要后续兼容适配，不能宣称一切 Obsidian 扩展均已无损迁移。

## 4. 思维导图 V3 规范

1. 中心主题居中、一级分支分布在左右两侧；不得退回 Markmap 式单侧大纲。
2. 知识节点必须是**真实 HTML 链接**，指向对应讲义的章节锚点，而不是不可点击的画布文本。
3. 一级分支必须使用 HTML `<details open>`，`<summary>` 原生支持折叠；JavaScript 负责增加体验而非创建基本内容。
4. SVG 连接线只做视觉辅助，失效不会影响正文、折叠、导航。
5. 默认可滚动浏览；缩放、适合窗口、展开全部和折叠全部由独立脚本渐进增强。
6. 地图宽度随交互缩放时同步调整外层滚动区域，防止内容被裁切在画布之外。
7. 页面需在浏览器脚本关闭、文件离线打开等情况下保留真实节点和链接。
8. 当前仅**气体动理论**提供结构化双侧导图样例；其他章节导图需要后续依据其内容自动提取或人工审阅后生成，不伪造知识结构。

```text

├── sources/                      # 权威 Markdown 文件
│   ├── physics/
│   │   └── 12 气体动理论.md
│   ├── discrete-math/            # 将离散数学 md 放到这里

│   ├── style.css                 # 全站阅读及 Callout 颜色
│   ├── app.js                    # 全站阅读交互
│   ├── mindmap.js                # 导图增强功能
│   ├── lab.js                    # 函数图像
│   ├── search-data.js           # 自动生成搜索索引
│   └── imported/                # 构建器复制相对引用的本地附件
├── tools/
│   ├── build.py                  # 批量转换主程序
```

**写入原则**：只手工维护 `sources/`、`config/`、`assets` 的共享代码和模板；不要把对生成 HTML 的直接改动当作永久维护手段，因为再次运行构建器会覆盖目标 HTML。

## 6. 从 Markdown 批量导入：真实操作流程

### 第一次配置环境（macOS）

安装 Python 3.11+、Node.js（推荐 LTS）。在知识库根目录打开终端：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm install
python tools/build.py --check
```

- `mistune` 负责 Markdown 解析，`beautifulsoup4` 负责结构转换。
- `mathjax-full` 构建时预渲染 LaTeX SVG。
- 上述依赖**仅构建时**需要，阅读端直接使用 HTML、CSS、JavaScript、SVG。

### 以后新增课程资料

将课程 Markdown 原样放入相应目录：

```text
sources/
  physics/
    12 气体动理论.md
    13 热力学基础.md
  discrete-math/
    01 命题逻辑.md
    02 等值式.md
  data-structures/
    02 线性表.md
```

在项目根目录执行：

```bash
source .venv/bin/activate
python tools/build.py --check
```

脚本会自动：

1. 扫描 `sources/<course-id>/**/*.md`；
2. 根据课程配置和原文件名生成页面路径；
3. 保护并渲染 LaTeX 表达式；
4. 转换 Markdown 标题、列表、表格、代码和 Obsidian Callout；
5. 为知识标题分配章节锚点；
6. 复制相对引用且存在的本地图片和附件；
7. 生成 `subjects/` 下的独立 HTML、首页课程链接和左侧分级导航；
8. 重新生成全局搜索索引；
9. 在 `docs/conversion-report.json` 写入迁移计数及告警；
10. 使用 `--check` 校验标题、公式、Callout 数量和本地文件链接。

新文件 **不需要**逐一写进 Python 源码；正常情况下只需复制 Markdown 后执行构建命令。

### 增加新的课程分类

编辑 `config/courses.json` 的 `courses` 数组：

```json
{
  "id": "computer-systems",
  "name": "计算机系统导论",
  "icon": "▣",
  "order": 40
}
```

然后创建 `sources/computer-systems/` 并放入 `.md` 文件。

`overrides` 可给特定文档指定固定的输出文件名和描述。建议一开始确定文件名，避免外部链接因日后重命名而改变。

### 资源文件怎么处理

- 标准 Markdown 图片：`![示意图](images/a.png)`，图片文件应与 MD 的相对路径对应；构建器会复制到 `assets/imported/`。
- 外部图片链接：保留外部 URL，但如果希望整个知识库**完全离线**，应先将图片下载到资料目录再引用。
- 生成式函数图：优先写成 HTML/SVG/JS 的可交互组件；例如气体动理论中的麦克斯韦分布图。并非每种图都必须制作成静态图片。
- Obsidian 的 `![[文件名]]`、`[[页面]]`、特殊插件引用目前**不应默认认为已完整支持**；导入前需批量检查、转换为标准链接，或等适配器补齐后再大规模导入。

## 7. 迁移准确性与验收

| 验收项 | V3 实现范围 |
|---|---|
| 原始笔记 | 不改写源文件；原文保留 |
| 标题数量 | 与 Markdown `#` 级标题核对 |
| LaTeX 数量 | SVG 包装数量与输入公式数量核对 |
| Callout 数量 | 与原始 `> [!type]` 记录数核对，包括嵌套 Callout |
| 链接与附件 | 检查本地文件是否存在 |
| 导图 | 默认 HTML 即可读；脚本加入后缩放、折叠、SVG 连线 |
| 批量导入 | 经过模拟新增第二门课程、两篇 Markdown、彩色 Callout、公式、图片、跨文档链接的构建测试 |

限制须如实处理：当前构建器不会对所有自定义 Markdown 插件语法逐一理解；标题 ID 使用顺序 `sec-XX`，**若重排章节，旧深层锚点可能改变**；当前搜索为简单全文关键词匹配；复杂大型知识库有必要升级稳定 ID 和搜索引擎。

## 8. 后续版本合理演进

**V3（现在）**：两处 UI 问题修复，阅读体验不倒退，真实批量导入。  
**V4**：补齐 Obsidian WikiLink、附件文件库、图片路径兼容、稳定章节 ID 和跨章节关系。  
**V5**：多种交互图像模板（函数曲线、算法可视化、数据结构图），并可从单篇 HTML 自动生成关联导图。  
**V6**：全文索引升级、个人知识关联图谱、可选本地全文/公式搜索、可选静态部署。  

**原则不变**：软件服务于读者，知识组织和阅读可靠性高于装饰性设计。
